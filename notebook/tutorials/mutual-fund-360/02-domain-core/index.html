Why Ravi’s PAN must be unrepresentable as plaintext

His folio needs a PAN (Indian tax ID) to reconcile across AMCs — and a PAN in a log file is a breach. First principle: make invalid or dangerous states impossible to construct, not merely discouraged. Enter the value object: a tiny type whose constructor validates and whose string form is always safe.

Step 2 — Freeze the entities

All entities are @dataclass(frozen=True): User, Portfolio, Folio, Scheme, Plan, NAV (with a superseded_by_id correction chain — old NAVs are never overwritten, only superseded). Frozen means no handler can mutate shared state as a side effect; change requires constructing the next version explicitly. Money and identity deserve immutability; the codebase agrees structurally, not just culturally.

Lesson

Immutability here isn’t aesthetic — it’s the reason no handler can corrupt shared money state as a side effect. When everything is frozen, every change is explicit, reviewable, and testable. Mutable domain objects make every bug report start with “who touched this last?”

Step 3 — Encode tax law as data + pure functions

The TaxRuleEngine is pure (no I/O): given FY rules, classify gains, apply the 2018-01-31 grandfathering cutoff (taxable = max(0, sale − max(acquisition, peak_Jan2018))), indexate with CII tables, distinguish equity/debt/hybrid by 65%/35% thresholds. Tax rules themselves are rows (FY, rates, exemptions, indexation flags), not code branches — when the Finance Act changes, you insert rows, not rewrite logic. Mental model: law changes yearly, code shouldn’t have to. Data-driven rules with a methodology version beat hardcoded rates every time.

Step 4 — Resolve schemes across time

Funds merge, rename, split. SchemeMappingService resolves any scheme as-of any date, follows multi-hop chains, computes conversion ratios, and raises on circular mappings rather than looping forever. Same lesson as curriculum graphs: prove structural properties in code.

What worked, what I’d change

Worked: the PAN pattern (8 tests) and frozen entities make whole bug classes unrepresentable. I’d change: the MethodologyVersion test/source drift found during verification (tests call .parse, code exposes from_string) — a 5-test failure from a rename that skipped the tests, the exact rot contracts are meant to prevent. Principle: types are executable documentation; keep them compiling against their tests. Next: Part 3 — the money math itself.
