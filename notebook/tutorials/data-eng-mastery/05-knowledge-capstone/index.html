Reading that query like an engineer

Four clauses, four jobs. SELECT with <=> computes cosine distance beside the row — no second system, no export. WHERE similarity >= :threshold (0.7) discards weak matches early instead of ranking noise. ORDER BY similarity DESC ranks what remains. LIMIT :k (10) caps work and screen space. Because the embedding lives in the same row, certification and keyword filters join in the same round trip — that join is the feature the sidecar architectures pay a sync job to imitate.

Two numbers carry contracts: 1024 (embedding width — change models, migrate data) and 0.7 (match floor — a product decision with an owner, per Part 2’s rule that magic numbers get names and dates). Your turn: find one magic number in your codebase without an owner. Assign it one today.

HNSW: the index that makes it fast

Without an index, every search compares against every row — fine at hundreds of concepts, hopeless at millions. HNSW (Hierarchical Navigable Small World) pre-builds shortcut layers over the vectors so a query descends greedily instead of scanning. Priya-sized data would survive a scan; the index is bought for headroom, honestly labeled as such.

The honest-scope rule again: match machinery to measured need. Under ~50 static graph nodes, sorted adjacency beats a graph database with an operator (Topic 4). Under thousands of vectors, HNSW beats a scan. In both cases the article states the crossover instead of pretending the heavy tool was always necessary.

When Priya asks “what first?”

Typed edges (prerequisite, enables, replaces, related) answer three questions: ancestors (what first), reverse lookup (what unlocks), depth-sorted paths minus mastered nodes. Kahn’s topological sort raises on cycles — a curriculum requiring A-before-B-before-A is broken by construction, and code should prove it. Walk one: Priya targets “Liquid Clustering”. Ancestors climb prerequisite edges (partitioning basics → file layout → clustering); mastered nodes drop out; the remainder depth-sorts into her reading order. The same walk powers “what unlocks” in reverse — finish clustering and the app can congratulate her with the exact doors it opened.

When agents ask instead of Priya

Same backend, third client: MCP tools (search, concept, path, progress, quiz, export) plus Obsidian vault exports. Mental model: client diversity tests service design — clean Part-3 services meant agents mapped to existing capabilities instead of demanding new endpoints. Design services so the third client is cheap; you won’t know what it is yet.

Agent safety, plainly: tools expose reads and quiz attempts — the same operations Priya’s screen performs, through the same auth and validation. No tool bypasses a gate Priya faces. The day an agent needs a capability Priya lacks (bulk export, admin reads), that tool gets its own auth review — capability and permission ship together, never apart.

Directing an AI agent at this knowledge layer

Failure modes of knowledge systems

  • Stale embeddings. Content edited, vectors not recomputed — meaning search lies quietly. Defense: the pipeline’s vectorize stage re-runs on publish (Part 4); edits outside the pipeline are the hole — close it by routing all writes through publish.
  • Threshold rot. 0.7 was right for last year’s content; new topics drift. Defense: the cutoff has an owner and a review habit, not just a value.
  • Dimension lock-in. New embedding model, old 1024-wide column. Defense: stated up front as the contract’s price (Topic 1 tradeoff) — migration planned, not discovered.
  • Graph cycles. A-before-B-before-A curricula. Defense: Kahn’s sort raises; the error names the cycle.
  • Agent overreach. A tool exposing more than its screen equivalent. Defense: capability parity review for every new tool.

Vocabulary (her words → our words)

  • Concept — one learnable idea with explanations, examples, traps.
  • Mastery (0–1, stored 0–1000) — measured command; 0.55 means “understanding”, 0.74 “application”.
  • SM-2 card — a flashcard with an ease and a next-review date.
  • Weak topic — weakness score above 0.4, with a typed reason.
  • Stratified exam — fair paper: 40/40/20 difficulty mix, seeded shuffle.
  • Idempotency receipt — proof a stage finished, so re-runs skip it.
  • Dead-letter queue — where failed jobs wait to be understood.
  • HNSW / tsvector — fast similarity index / keyword search index.
  • MCP tool — one backend capability, callable by AI agents.
  • JWT rotation — short access tokens plus renewable refresh tokens.

What worked, what I’d change, what’s next

Worked: spec-first structure surviving a year; pure-function engine testable in milliseconds; one store serving three query kinds; gates deciding while models draft; sources of truth named per concern.

Changed already (resolved, evidenced): client-awarded XP → server-side (BUG-017). Untested math → 86 tests. Fixture rows polluting production-shape data → seed/teardown discipline. Each encoded — in code, tests, or process — so it teaches forever.

I’d change: write the dimension contract before the first embedding lands (discovered, not designed). Collapse the duplicate flat/integration test files into one layout. Promote the progress tracker from honest record to weekly ritual.

Investigate next: calibrating mastery weights against logged outcomes (judgment → evidence); hybrid keyword-plus-vector ranking with measured lifts; per-section time estimates from attempt timestamps. Each a small experiment — hypotheses first, numbers after. Your turn: pick one, write its hypothesis in one sentence, and name the measurement that would confirm it.

Principle worth keeping
